# Claude Code automations for this repository

5 November 2026. Generated by running the `claude-automation-recommender`
skill from the official `claude-code-setup` plugin against this codebase, and
then implementing its recommendations. The skill itself is read-only; everything
below was added by hand afterwards and is checked in so every agent and every
machine gets the same setup.

## Codebase profile the recommendations were based on

Next.js with React and TypeScript, 211 files under `app/`, `components/` and
`lib/`. Tailwind with a shadcn-style component layer, `recharts` for charts,
Supabase for the database with 126 forward-only migrations, 33 guard scripts
under `scripts/`, three GitHub Actions workflows, and ESLint extending
`next/core-web-vitals` with `jsx-a11y/alt-text`, `@next/next/no-img-element`
and `eqeqeq` raised to errors.

## Plugins (`.claude/settings.json`, `enabledPlugins`)

Enabled at repository scope so every agent working here has the same set:
`ecc` (reviewers and build fixers), `superpowers` (brainstorming,
test-driven development, verification before completion),
`caveman` (terse output and small surgical edit agents),
`taste-skill` (frontend design judgement),
`task-observer` (watches long runs),
`headroom` (startup hooks) and
`claude-code-setup` (the recommender that produced this file).

## MCP servers (`.mcp.json`)

| Server | Why this codebase needs it |
|---|---|
| `playwright` | The definition of done in `docs/design/2026-11-05-ux-redo-goal.md` requires that a screen has been opened in a browser and looked at, at 375, 768, 1024 and 1440 px. Nothing else in the repository can do that. The default viewport is set to 1440x900. |
| `context7` | Live documentation for Next.js, Supabase, Tailwind and recharts, so an agent does not answer an API question from memory. |

Both are pinned to an exact version. Raise the version deliberately, in its own
pull request, not with `@latest`.

## Hooks (`.claude/settings.json`, `hooks`)

| Hook | Event | What it does |
|---|---|---|
| `.claude/hooks/protect-paths.mjs` | `PreToolUse` on `Edit`, `Write`, `MultiEdit`, `NotebookEdit` | Refuses a write to any `.env` file, and refuses an edit to a migration under `supabase/migrations/` that is already on `origin/main`. The existing `permissions.deny` blocks a *read* of `.env`; it does not block a write. The migration rule exists because migrations are forward-only and production has no point-in-time recovery: editing an applied migration puts the repository and production permanently out of step and nothing detects it. A migration not yet on `origin/main` is still a draft and may be edited. |
| `.claude/hooks/lint-edited-file.mjs` | `PostToolUse` on `Edit`, `Write`, `MultiEdit` | Runs ESLint on the one file that was just edited and reports the output. It never blocks. It exists because this repository's accessibility rules report as **warnings**, so ESLint exits 0 and a reader of the exit code alone would miss exactly the findings that matter here. |

Both hooks are Node scripts so they behave the same on Windows, macOS and
Linux, and both read the hook payload from standard input.

## Subagent (`.claude/agents/kima-screen-reviewer.md`)

Reviews one screen against the definition of done item by item: word and icon
rather than colour alone, an em dash rather than a zero for an unavailable
figure, FR and EN parity with the copy in the dictionary rather than inline, the
four axes kept separate, no claimed status the data does not support, keyboard
and assistive-technology correctness, SVG icons, and the four widths. It is
read-only and it is told to answer "could not be verified" rather than guess.

This sits alongside the three existing agents and the external reviewers
`AGENTS.md` already names (`ecc:code-reviewer`, `ecc:security-reviewer`).

## Skills (`.claude/skills/`)

Both are user-invocable only (`disable-model-invocation: true`), because both
describe actions with consequences that a person should choose to take.

| Skill | What it is for |
|---|---|
| `/create-migration` | Writing a Supabase migration the forward-only way: naming, expand-only shape, money and date types, row level security with an index for the policy, no `PUBLIC` grant on a definer function, and what the pull request must say about what cannot be undone. It also states that `supabase/**` is Agent A's path. |
| `/pr-check` | The merge gates: the test commands, the 300-changed-line limit, path ownership, the definition of done, stating what could not be verified, green checks for that exact head, and the post-merge production verification. |

## Not adopted, and why

A type-check hook on every edit was considered and rejected: `tsc --noEmit`
covers the whole project and is far too slow to run after each edit. Type
checking stays where it is, in `npm run typecheck` and in CI.
